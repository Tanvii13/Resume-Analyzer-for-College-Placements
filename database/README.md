## 1. Project Overview

The database supports the initial backend workflow of the Resume Analyzer for College Placements project. It stores account information, resume metadata, parsed resume sections, and processing status.

The schema is designed to support user stories US-01 to US-04 and integrates with the backend services responsible for authentication, file validation, and resume parsing.

## 2. Sprint 1 Scope

| User Story | Database Support |
|---|---|
| US-01: Account Access | Account information and role mapping |
| US-02: Resume Upload | Resume metadata and private file-storage reference |
| US-03: Resume Parsing | Parsed sections such as education, skills, projects, and experience |
| US-04: Invalid Resume Handling | Processing status and readable error messages |

## 3. Database Structure

```text
database/
└── schema.sql
```

The `schema.sql` file defines the database tables, relationships, constraints, indexes, and default role records.

### Main Data Areas

- **Accounts and Roles:** Stores account details and role assignments.
- **Resume Metadata:** Stores file information and a `storage_key` reference.
- **Parsed Resume Sections:** Organises extracted resume content into sections.
- **Processing Status:** Records processing outcomes and error messages.

## 5. Setup and Execution

### Prerequisites

Ensure PostgreSQL is running and the `resume_analyzer` database exists.

Create the database if required:

```sql
CREATE DATABASE resume_analyzer;
```

### Run the Schema

**Using pgAdmin:**
1. Open the `resume_analyzer` database.
2. Open Query Tool.
3. Load `database/schema.sql`.
4. Execute the SQL statements.

**Using the terminal:**

```bash
psql -U postgres -d resume_analyzer -f database/schema.sql
```

Replace `postgres` with your PostgreSQL username if necessary.

## 6. Design and Validation

The schema includes the following data-integrity controls:

- UUID-based identifiers and foreign-key relationships.
- `TIMESTAMPTZ` fields for timestamp storage.
- Check constraints and indexes.
- Safe insertion of default roles when they do not already exist.
- Resume file-size constraints: greater than 0 bytes and at most 5 MiB (5,242,880 bytes).

The schema uses `CREATE TABLE IF NOT EXISTS`. Rerunning it does not automatically modify existing table columns or constraints; use database migrations for such changes.

## 7. Security and Data Privacy

- Original PDF/DOCX files are stored in private file storage rather than directly in PostgreSQL. The `storage_key` references the stored file.
- Passwords must never be stored in plain text. The `password_hash` field should contain a secure hash generated by the authentication layer.
- Database credentials and other secrets must not be committed to GitHub.
- Resume access should be restricted to authorised users and application components.

The backend must enforce upload validation and access controls in addition to database constraints.

## 8. Verification

After running the schema, verify that the expected tables, relationships, indexes, and constraints exist.

Example query to list tables:

```sql
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public'
  AND table_type = 'BASE TABLE'
ORDER BY table_name;
```

Also verify that the backend can connect to the database and that invalid data is rejected by the configured constraints.
